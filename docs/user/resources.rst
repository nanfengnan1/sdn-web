按 Agent 管理独立资源
================================================================

“租户与网络”的 **Agent 资源工作台** 提供表单操作，不需要编写完整 JSON。
先选择已接管的 Agent，表单会自动携带节点 UUID。页面下方保留全局声明式配置，
“高级 JSON 编辑器”仍可用于完整候选编辑。

配置条目与职责
----------------------------------------------------------------

工作台按“租户与网络、二层网络 BD、接口、隧道、路由”分组。
“接口”是独立条目；“路由”下选择“BGP、OSPF”；“隧道”下目前仅开放“VXLAN”。
每个条目只提供本类资源的表单、配置目标和运行查询。

* 接口状态、MTU、MAC 和所有 IPv4/IPv6 地址（包括 BD 的三层地址）在“接口”配置。
* BD 属性和成员关系在“二层网络 BD”配置，VXLAN 加入/移出 BD 也使用此处的成员操作。
* “隧道 → VXLAN”负责 VXLAN 隧道创建和删除；BGP 与 OSPF 的协议参数在各自的路由子条目配置。EVPN 属于 BGP，在“路由 → BGP”中配置和查询。

当前工作台不开放静态路由配置入口，也不展示其他隧道类型。

切换分类不会提交配置，已保存的编辑仍属于同一候选，可以一起预览、提交。
未加入候选的表单输入会重置；运行查询的筛选条件、旧结果和错误也随分类切换清除。

配置目标、候选与实际状态
----------------------------------------------------------------

资源表和关系树显示 Controller 的配置目标；恢复或新建候选后显示该候选内容。
页面标出 Desired 版本、Agent 版本、候选基础版本和草稿版本。
这些内容不等于设备当前状态。实际状态由各分类下方的“运行状态查询”读取，
显示来源、采集时间、Agent 版本、stale 标记和错误。查询失败不会显示为成功的空表。
Controller 的 Desired 是提交意图：Agent 执行失败后即使回滚成功，Desired 也不会
自动退回旧值。应查看失败 Job 和运行查询，核对后显式提交修正目标。

租户关系树包含空 VRF、租户下的 BD、成员端口、VXLAN 和 BD 的三层地址。
未绑定租户的 BD、未加入 BD 的 VXLAN 也会显示。关系树只展示 BD 的地址关联，
地址统一在“接口”页编辑，不会创建另一份网关配置。

第一步：资源基线
----------------------------------------------------------------

* 空且已接管的节点可直接新建资源候选。
* 有 Agent Running 配置、但尚未建立 Controller 资源目标的节点显示 ``unmanaged``。
* 原来的 NodeProfile/Tenant/Network 声明式模型显示 ``legacy``。

后两种模式需要点击“验证并导入资源”，确认当前 Agent 版本。Controller 读回验证
已有资源，建立独立资源基线；验证失败会拒绝导入。导入本身不下发网络变更。
存在未提交候选时先完成或丢弃候选，避免基线改变后继续编辑旧版本。

第二步：编辑、预览和提交
----------------------------------------------------------------

1. 点击“新建资源候选”。
2. 选择分类与资源操作，填写表单并点击“加入候选”。
3. 可以继续添加多项操作，也可以选择另一个 Agent 在同一候选中编辑。
   每次保存使用当前草稿版本；冲突时重新读取并核对候选，不覆盖其他操作者的修改。
4. 点击“预览全部变更”，展开每个节点查看依赖排序后的操作。
5. 点击“提交配置”并确认，跳转到 Job。只有最终任务成功并完成读回验证才算配置成功。

可选字段留空表示不修改已有值。布尔选择支持显式关闭；数字 ``0`` 不会被丢弃。
删除或解绑操作只填写对象识别字段，由 Controller 使用受管目标补齐执行信息。
如果 Agent 没有声明某操作及回滚能力，该项显示不可选；后端也会校验能力。
viewer 角色不能导入、编辑或提交，只能查看和查询。

保存请求超时后，页面尝试重新读取候选。请检查版本和资源是否已存在，避免重复创建。
提交结果不确定时使用“重试原提交”，浏览器保留原幂等键以找回任务；不要重新创建提交。
恢复候选、待确认提交 ID 存在当前标签页的 sessionStorage，令牌只保存在内存。

只创建租户，然后追加网络
----------------------------------------------------------------

第一笔提交：选择“租户与网络 → 创建租户 VRF”，填写 ``TENANT-A`` 和路由表 ``1001``，
加入候选、预览、提交。这只创建 VRF，不隐式创建 BD、VXLAN 或 BGP 实例。

任务成功后回到资源页，新建下一笔候选：

1. “二层网络 BD → 创建 BD”：填写 ``br10``。
2. “租户与网络 → BD 加入租户”：选择 ``br10`` 与 ``TENANT-A``。
3. 在“接口 → 接口 / BD 添加地址”填写 ``br10`` 与 ``192.168.10.254/24`` 或 IPv6 前缀。
4. 在“二层网络 BD → BD 添加成员接口”添加接入口，或添加已在“隧道 → VXLAN”创建的隧道。
5. 预览后提交。这些操作不会再次创建已有 VRF。

L3VNI 独立绑定：先在目标 VRF 中准备三层 BD 与对应 VXLAN 及成员关系，
然后选择“绑定 L3VNI”填写 ``TENANT-A`` 和 ``50000``。
该动作只绑定已有三层 VNI，不自动创建隧道；不满足依赖时 Controller 会拒绝计划。
删除时先移除地址、成员和租户引用等依赖，再删除被引用对象。
删除 VRF、BD 或 VXLAN 时，Controller 自动清理同名接口的属性目标；
地址、成员、协议引用等不会被悄悄删除，需要先显式处理。

各分类支持的功能
----------------------------------------------------------------

.. list-table:: 资源和查询
   :header-rows: 1
   :widths: 20 45 35

   * - 分类
     - 配置表单
     - 运行查询
   * - 租户与网络
     - VRF 创建/删除，L3VNI 绑定/解绑，BD 加入/移出租户
     - VRF 与路由表
   * - 二层网络 BD
     - BD 创建/修改/删除，成员管理，STP/MTU/MAC/老化计时，ARP/ND 抑制
     - BD、成员、MAC/FDB、ARP/ND 邻居
   * - 接口
     - 接口 Up/Down、MTU/MAC、IPv4/IPv6 地址增删
     - 接口、地址
   * - 隧道 → VXLAN
     - 隧道创建/删除
     - VNI、VTEP、端口及隧道详情
   * - 路由 → BGP
     - 实例、邻居/组，IPv4/IPv6 激活，Network/重分发，RD/RT，EVPN、Type-5
     - BGP 概要/邻居/路由、EVPN 路由与 VNI
   * - 路由 → OSPF
     - OSPFv2/v3 实例、接口，OSPFv2 网段
     - 概要、接口、邻居、LSDB、路由

BD 级 ARP/ND 抑制策略作用于当前及未来的 VXLAN 成员，不修改主机接入口的行为。
它持久保存为 ``bridgePolicies``，不是 Linux Bridge 的原生全局标志。
**邻居抑制不等于主动 ARP/ND 探测或 MAC 保活。**

查询支持的地址族和 OSPF 版本来自 Agent 能力声明。未知 VRF、BD 或接口会显示错误；
空结果明确显示“查询成功，没有匹配的运行状态记录”。下一页使用不透明游标，
运行数据发生变化时游标可能失效，此时重新查询即可。

IPv6 地址和 OSPFv3 还要求节点操作系统启用 IPv6，并具备所需的接口地址。
旧 EVPN 实验的 ``configureSystem`` 示例会关闭 IPv6；应先通过受管的
``NODE_NETWORK`` 配置显式调整系统开关。地址表单不会隐式修改整台节点的 sysctl。

承载 IPv6 主机的业务 SVI 还必须有可用的链路本地地址。若沿用了 IPv4 实验的
``addrgenmode none``，仅添加全局 IPv6 地址不足以保证冷启动邻居解析。
通过地址表单为业务 SVI 配置该链路内唯一的 ``fe80::/64`` 地址，并在地址查询中
确认 DAD 完成；例如 MAC 为 ``02:00:00:00:00:10`` 的 br10 可使用
``fe80::ff:fe00:10/64``。已启用接口仅改为 ``addrgenmode eui64`` 不会立即补生成地址，
应显式配置，避免为生成地址而中断现有业务。无地址的 L3VNI SVI br50000 仍可保持
``addrgenmode none``。不要把主机先 ping 网关后的被动学习当作冷启动修复。

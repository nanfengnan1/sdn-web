按 Agent 管理独立资源
================================================================

“租户与网络”的 **Agent 资源工作台** 提供表单操作，不需要编写完整 JSON。
先选择已接管的 Agent，表单会自动携带节点 UUID。页面下方保留全局声明式配置，
“高级 JSON 编辑器”仍可用于完整候选编辑。

配置条目与职责
----------------------------------------------------------------

工作台按“租户与网络、二层网络 BD、接口、隧道、路由”分组。
“接口”是独立条目；“路由”下选择“BGP、OSPF”；“隧道”下目前仅开放“VXLAN”。
每个条目只提供本类资源的表单、配置目标和运行查询。

* 接口状态、MTU、MAC 和所有 IPv4/IPv6 地址（包括 BD 的三层地址）在“接口”配置。
* BD 属性和成员关系在“二层网络 BD”配置，VXLAN 加入/移出 BD 也使用此处的成员操作。
* “隧道 → VXLAN”负责 VXLAN 隧道创建和删除；BGP 与 OSPF 的协议参数在各自的路由子条目配置。EVPN 属于 BGP，在“路由 → BGP”中配置和查询。

当前工作台不开放静态路由配置入口，也不展示其他隧道类型。

切换分类不会提交配置，已保存的编辑仍属于同一候选，可以一起预览、提交。
未加入候选的表单输入会重置；运行查询的筛选条件、旧结果和错误也随分类切换清除。

配置目标、候选与实际状态
----------------------------------------------------------------

资源表和关系树显示 Controller 的配置目标；恢复或新建候选后显示该候选内容。
页面标出 Desired 版本、Agent 版本、候选基础版本和草稿版本。
这些内容不等于设备当前状态。实际状态由各分类下方的“运行状态查询”读取，
显示来源、采集时间、Agent 版本、stale 标记和错误。查询失败不会显示为成功的空表。
Controller 的 Desired 是提交意图：Agent 执行失败后即使回滚成功，Desired 也不会
自动退回旧值。应查看失败 Job 和运行查询，核对后显式提交修正目标。

租户关系树包含空 VRF、租户下的 BD、成员端口、VXLAN 和 BD 的三层地址。
未绑定租户的 BD、未加入 BD 的 VXLAN 也会显示。关系树只展示 BD 的地址关联，
地址统一在“接口”页编辑，不会创建另一份网关配置。

第一步：资源基线
----------------------------------------------------------------

* 空且已接管的节点可直接新建资源候选。
* 有 Agent Running 配置、但尚未建立 Controller 资源目标的节点显示 ``unmanaged``。
* 原来的 NodeProfile/Tenant/Network 声明式模型显示 ``legacy``。

后两种模式需要点击“验证并导入资源”，确认当前 Agent 版本。Controller 读回验证
已有资源，建立独立资源基线；验证失败会拒绝导入。导入本身不下发网络变更。
存在未提交候选时先完成或丢弃候选，避免基线改变后继续编辑旧版本。

第二步：编辑、预览和提交
----------------------------------------------------------------

1. 点击“新建资源候选”。
2. 选择分类与资源操作，填写表单并点击“加入候选”。
3. 可以继续添加多项操作，也可以选择另一个 Agent 在同一候选中编辑。
   每次保存使用当前草稿版本；冲突时重新读取并核对候选，不覆盖其他操作者的修改。
4. 点击“预览全部变更”，展开每个节点查看依赖排序后的操作。
5. 点击“提交配置”并确认，跳转到 Job。只有最终任务成功并完成读回验证才算配置成功。

可选字段留空表示不修改已有值。布尔选择支持显式关闭；数字 ``0`` 不会被丢弃。
删除或解绑操作只填写对象识别字段，由 Controller 使用受管目标补齐执行信息。
如果 Agent 没有声明某操作及回滚能力，该项显示不可选；后端也会校验能力。
viewer 角色不能导入、编辑或提交，只能查看和查询。

保存请求超时后，页面尝试重新读取候选。请检查版本和资源是否已存在，避免重复创建。
提交结果不确定时使用“重试原提交”，浏览器保留原幂等键以找回任务；不要重新创建提交。
恢复候选、待确认提交 ID 存在当前标签页的 sessionStorage，令牌只保存在内存。

只创建租户，然后追加网络
----------------------------------------------------------------

第一笔提交：选择“租户与网络 → 创建租户 VRF”，填写 ``TENANT-A`` 和路由表 ``1001``，
加入候选、预览、提交。这只创建 VRF，不隐式创建 BD、VXLAN 或 BGP 实例。

任务成功后回到资源页，新建下一笔候选：

1. “二层网络 BD → 创建 BD”：填写 ``br10``。
2. “租户与网络 → BD 加入租户”：选择 ``br10`` 与 ``TENANT-A``。
3. 在“接口 → 接口 / BD 添加地址”填写 ``br10`` 与 ``192.168.10.254/24`` 或 IPv6 前缀。
4. 在“二层网络 BD → BD 添加成员接口”添加接入口，或添加已在“隧道 → VXLAN”创建的隧道。
5. 预览后提交。这些操作不会再次创建已有 VRF。

L3VNI 独立绑定：先在目标 VRF 中准备三层 BD 与对应 VXLAN 及成员关系，
然后选择“绑定 L3VNI”填写 ``TENANT-A`` 和 ``50000``。
该动作只绑定已有三层 VNI，不自动创建隧道；不满足依赖时 Controller 会拒绝计划。
删除时先移除地址、成员和租户引用等依赖，再删除被引用对象。
删除 VRF、BD 或 VXLAN 时，Controller 自动清理同名接口的属性目标；
地址、成员、协议引用等不会被悄悄删除，需要先显式处理。

各分类支持的功能
----------------------------------------------------------------

.. list-table:: 资源和查询
   :header-rows: 1
   :widths: 20 45 35

   * - 分类
     - 配置表单
     - 运行查询
   * - 租户与网络
     - VRF 创建/删除，L3VNI 绑定/解绑，BD 加入/移出租户
     - VRF 与路由表
   * - 二层网络 BD
     - BD 创建/修改/删除，成员管理，STP/MTU/MAC/老化计时，ARP/ND 抑制
     - BD、成员、MAC/FDB、ARP/ND 邻居
   * - 接口
     - 接口 Up/Down、MTU/MAC、IPv4/IPv6 地址增删
     - 接口、地址
   * - 隧道 → VXLAN
     - 隧道创建/删除
     - VNI、VTEP、端口及隧道详情
   * - 路由 → BGP
     - 实例、邻居/组，IPv4/IPv6 激活，Network/重分发，RD/RT，EVPN、Type-5
     - BGP 概要/邻居/路由、EVPN 路由与 VNI
   * - 路由 → OSPF
     - OSPFv2/v3 实例、接口，OSPFv2 网段
     - 概要、接口、邻居、LSDB、路由

BD 级 ARP/ND 抑制策略作用于当前及未来的 VXLAN 成员，不修改主机接入口的行为。
它持久保存为 ``bridgePolicies``，不是 Linux Bridge 的原生全局标志。
**邻居抑制不等于主动 ARP/ND 探测或 MAC 保活。**

查询支持的地址族和 OSPF 版本来自 Agent 能力声明。未知 VRF、BD 或接口会显示错误；
空结果明确显示“查询成功，没有匹配的运行状态记录”。下一页使用不透明游标，
运行数据发生变化时游标可能失效，此时重新查询即可。

IPv6 地址和 OSPFv3 还要求节点操作系统启用 IPv6，并具备所需的接口地址。
旧版 EVPN 实验的 ``configureSystem`` 曾关闭 IPv6；当前 Controller 改为启用 IPv6 和转发。
沿用旧配置时，通过受管的 ``NODE_NETWORK`` 配置显式调整系统开关。
地址表单不会隐式修改整台节点的 sysctl。

承载 IPv6 主机的业务 SVI 还必须有可用的链路本地地址。若沿用了 IPv4 实验的
``addrgenmode none``，仅添加全局 IPv6 地址不足以保证冷启动邻居解析。
通过地址表单为业务 SVI 配置该链路内唯一的 ``fe80::/64`` 地址，并在地址查询中
确认 DAD 完成；例如 MAC 为 ``02:00:00:00:00:10`` 的 br10 可使用
``fe80::ff:fe00:10/64``。已启用接口仅改为 ``addrgenmode eui64`` 不会立即补生成地址，
应显式配置，避免为生成地址而中断现有业务。无地址的 L3VNI SVI br50000 仍可保持
``addrgenmode none``。不要把主机先 ping 网关后的被动学习当作冷启动修复。

VPP 节点运行查询
----------------------------------------------------------------

VPP 节点的查询区显示“VPP 数据面”。“隧道 → VXLAN”展示逻辑名称、原生接口、
VNI、本地 VTEP、地址族、远端数和 BUM 数；展开行查看目的 MAC 与远端 VTEP 映射。
IPv4/IPv6 筛选指外层 VTEP 地址族，两种 underlay 均可承载 IPv4/IPv6 业务流量。
“查询邻居”可筛选远端 VTEP；VRF、BD 与接口名称也可组合筛选。

“接口”包括 LCP 接口、BVI 和原生 VXLAN，FDB 区分本地、远端和 BVI 条目。
来源 vpp 表示来自原生 VPP 查询；FRR 的 BGP/EVPN 查询仍显示协议后端来源。
viewer 可以执行这些查询。没有远端时源地址型 VXLAN 接口仍会保留，展开表为空
不代表接口消失；查询失败与空结果分别显示。

VPP 邻居保活
------------

VPP Agent 声明 neighbor-keepalive/v1 能力时，可设置节点级
NEIGHBOR_KEEPALIVE / SET，数据为 neighborKeepalive.enabled（true / false）。
默认关闭；Linux Agent 不支持。不使用 DELETE 关闭。

在 Web“二层网络 BD”选择“邻居保活（节点开关）”，加入候选、预览并提交。
使用已有导入/候选流程，不能绕过节点能力或 revision 检查。
NEIGHBOR_KEEPALIVE_STATUS 查询来自 VPP，支持 IPv4/IPv6，显示策略和每 IP
探测状态、尝试次数、确认时间、发送错误与容量计数。

保活只针对已学习到的本地动态 MAC/IP：单播 ARP Request / IPv6 NS
由 VPP 发送，有效学习续期，三次失败撤销对应 IP；同 MAC 的其他 IP 保留。
不是 ARP/ND 抑制，也不是向远端周期性发送 Type-2。
启用需要配套新版 VPP/Agent 镜像及 neighbor_keepalive_plugin.so；
MAC ageing 为 0 或 >=120 秒，默认 300 秒满足要求。Linux 节点不显示此开关。

VXLAN 外层 VRF：创建与在线修改
--------------------------------

VPP 节点支持为 VXLAN 设置外层路由表，并在创建后修改。
外层 VRF 用于到远端 VTEP 的封装路由及接收隧道匹配；内层租户 VRF 仍由
BD/BVI 与 TENANT 的关系决定。修改外层表不改变 VNI、原生接口编号或 BD 绑定。

使用前先准备同地址族的 VPP 路由表、Linux VRF 控制映射以及到远端 VTEP 的
底层路由。通过 Controller 管理时，非零外层表必须先以 TENANT 资源创建；
这个承载 VRF 可以没有业务 BD 和 L3VNI。表 ID 0 表示 VPP 默认表，不能把
Linux main 的数字 254 填进此字段。253、254、255 和 4294967295 被拒绝。

Web 中选择支持 ``vxlan-encap-vrf/v1`` 的节点，进入“隧道 / VXLAN”：

1. 创建 VXLAN 时可以填写“外层 VRF 表 ID”。
2. 对已有隧道选择“修改 VXLAN 外层 VRF”，填写名称及目标表 ID。
3. 加入候选、预览计划后提交；回到默认表时明确填写 0。
4. 运行查询的“外层 VRF 表 ID”显示 VPP 实际值。

Agent / Controller 资源操作示例：

.. code-block:: json

   {
     "code": "VXLAN",
     "action": "SET",
     "vxlan": {"name": "vx50000", "encapVrfId": 100}
   }

CREATE 使用相同的可选字段，同时提供 local、vni 等创建参数。
SET 只修改 encapVrfId 和可选的 underlay；不接受 local、vni、port 或 learning
的身份修改。已有 underlay 留空表示保留，不表示清除。显式指定的 underlay
必须是 LCP 接口，而且 Linux 与 VPP 两侧均已属于目标外层表。
省略 underlay 时，非零表使用对应 Linux VRF 作为控制镜像的底层设备；
VXLAN 的 bridge master 仍然是原有租户 BD。

此操作不会替用户迁移物理网卡、调整 BGP 管理连接或创建远端 VTEP 路由。
先完成承载网络准备，再修改隧道；切换可能短暂中断通信。要删除旧承载 VRF，
先单独提交所有隧道的切换，再删除 VRF；仍被引用的表不能删除。

需要同时更新 VPP 插件/API/适配器、Agent、Controller 和 Web。
旧节点或 Linux 数据面不显示修改入口；Linux 后端拒绝非零 encapVrfId。
设备配置由适配器持久化，重新加载时仍需先恢复启动配置管理的 Underlay/LCP。

FRR 下一跳解析也需要承载可达性
----------------------------------------

当 BGP EVPN 实例仍在 default VRF，而数据 Underlay 已迁移到 OUTER100，
仅在 VPP 表 100 中存在路由还不够：默认 BGP 实例也必须解析远端 VTEP，
否则 EVPN 路由可能已接收但无 valid/best 标记，进而撤销租户路由和远端 MAC。

可按部署设计向控制面 VRF 泄漏真实承载路由。例如远端 VTEP
192.0.2.2 已经可以通过 OUTER100 中的 uplink 直连访问时，在 FRR 配置：

.. code-block:: text

   ip route 192.0.2.2/32 uplink nexthop-vrf OUTER100

IPv6 对应使用 ipv6 route <VTEP>/128 uplink nexthop-vrf OUTER100。
这是一条经真实 Underlay 出口解析的路由，不能用黑洞或伪造直连路由来让
EVPN 强行选路。使用其他 IGP/BGP 泄漏方案时同样验证 show ip nht / show ipv6 nht。
接口移动、该路由泄漏及其启动恢复由承载网络配置负责，
VXLAN SET 不自动配置它们。当前 Agent 的 STATIC_ROUTE 资源没有 nexthop-vrf 字段；
可在部署时的 FRR 配置文件中维护此项。

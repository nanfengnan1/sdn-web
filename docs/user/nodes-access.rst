访问权限与节点纳管
==================

访问令牌是什么
--------------

访问令牌是一串供 Gateway 和 Controller 核对身份的凭据。当前系统使用预配置的两类令牌，没有用户名密码注册页面。

.. list-table:: 令牌与权限
   :header-rows: 1
   :widths: 20 45 35

   * - 类型
     - 可以做什么
     - 使用位置
   * - ``admin``
     - 查询、节点纳管、编辑候选、预览及提交配置
     - Web 登录；Controller 管理客户端
   * - ``viewer``
     - 查询节点、配置、已知候选、任务及拓扑
     - Web 只读登录
   * - ``agent``
     - Agent 节点注册与心跳
     - Agent 服务配置；不能用于 Web 登录

Docker 环境通过 Controller 项目的 ``docker/manage.py init`` 生成 ``docker/state/tokens.json``。自建部署由管理员设置 Gateway 与 Controller 一致的 ``SDN_ADMIN_TOKEN``、``SDN_VIEWER_TOKEN``。管理员令牌至少 16 字节，配置了只读令牌时，它也至少 16 字节且必须不同。

令牌只应交给对应权限的使用者。不要将实际值放进 Vue 的 ``config.js``、源代码、URL、截图或共享测试报告。

登录与退出
----------

在登录页填写令牌并点击“连接控制台”。页面先查询身份，成功后右上角显示“管理员”或“只读”。点击“断开连接”退出。

令牌只保存在页面内存，未存入 localStorage 或 sessionStorage；刷新页面会要求重新输入。候选 ID 和提交请求标识可以保存在当前标签页的 sessionStorage，以便重新登录后找回操作，它们不是登录凭据。

隐藏修改按钮只改善只读体验。Gateway 和 Controller 还会分别检查权限，绕过页面直接请求接口也不会获得写权限。

理解节点状态
------------

“节点管理”每页最多显示 50 个节点，统计卡片仅统计当前页。使用“刷新节点”“上一页”“下一页”更新和翻页。

.. list-table:: 节点字段
   :header-rows: 1
   :widths: 28 72

   * - 字段
     - 含义
   * - 节点 ID
     - Controller 确认的节点 UUID；配置 placement 使用它，不使用容器名称替代
   * - Endpoint
     - Controller 连接 Agent 的 gRPC 地址
   * - Instance
     - 当前 Agent 进程实例标识；不等同于持久节点身份
   * - ``INIT``
     - 身份/连接正在初始化
   * - ``RUNNING``
     - 管理连接有效；不表达数据面或业务流量健康程度
   * - ``DOWN``
     - Controller 未能持续收到有效心跳；不代表已删除节点配置
   * - Agent 版本
     - 本节点已提交 Running 配置的 revision，不是软件版本号
   * - 已纳管
     - Controller 已经核对节点并建立管理基线

点击“详情”可查看能力列表、操作对应后端和是否支持回滚，以及完整节点 JSON。观测错误会单独显示，不能把存在观测错误的节点当作确认健康。

执行纳管
--------

1. 用管理员身份查看目标节点详情，核对 UUID、endpoint 和当前版本。
2. 点击“纳管”。空白节点不勾选“允许接管已有配置”。
3. 点击“确认纳管”。Controller 重新读取 Agent 状态并核对版本。
4. 页面刷新后确认“已纳管”。如果版本冲突，重新查询并核对，不反复使用旧状态提交。

“允许接管已有配置”用于显式允许建立已有 Agent 管理状态的基线。它不会把任意手工 ``ip`` / ``vtysh`` 配置自动转换成 Controller 的租户和网络对象，也不会自动修正外部配置漂移。

容器网络命名空间被重建后，即使数据库和 FRR 文件还在，Linux 接口与链路也可能已经消失。不要仅凭“已纳管”或版本号判断网络已恢复，先核对实际状态，见 :doc:`troubleshooting`。

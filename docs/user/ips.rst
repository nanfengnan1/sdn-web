IPS 页面与 Snort 配置
===============================

先确认节点
----------

使用配套的新 Controller 和 VPP Agent 镜像。Agent 必须开启 IPS 并成功启动 Snort，
页面才允许提交对应操作。节点显示 RUNNING 后确认纳管；Viewer 账户只能查看。

规则配置
--------

1. 左侧进入 **IPS 配置**，选择目标 Agent。
2. 首次使用独立资源时，执行验证并导入基线。
3. 点击 **新建资源候选**，选择 **创建规则**。
4. 填写 SID 与完整单行规则，点击 **加入候选**。
5. 添加检查接口，填写 VPP 原生三层接口/BVI 名称和 input/output/inout 方向。
6. **预览全部变更**，确认后 **提交配置**。
7. 到任务页等待成功，再查询 **实际生效规则** 和 **IPS 服务与重载状态**。

例：先用只记录的规则确认命中，再按需要改成 drop：

.. code-block:: text

   alert icmp any any -> any any (msg:"ICMP audit"; sid:1000001; rev:1;)

SID 必须与规则文本相同。修改、删除也要进入候选并提交，
仅在表单输入或保存候选不会改变设备。候选可能包含其他页面的修改，
提交前应核对整个计划。

一个节点的托管规则作用于该节点全部 IPS 绑定方向，当前没有每租户独立实例。
接口名应来自 VPP 实际接口查询，例如 bvi1；普通 BD 二层成员不适用。
绑定变化会短暂切换接口管理状态。默认断连策略为 drop：
已绑定方向在 Snort 断连时阻断流量。

基础参数与规则分开
------------------

宿主机管理员通过 agent.conf 的 ips.configFile 指定只读 Lua 文件，
设置 HOME_NET、检测模块和日志等。Web 规则更新不会重写该源文件，
基础配置不能覆盖 Agent 管理的 ips.rules/ips.include。

修改基础文件后，在宿主机执行：

.. code-block:: console

   docker exec <Agent容器名> sdn-snort-reload

也可以在 Agent 启用 ips.autoReload；该开关本身需要重启生效。
部署、目录挂载和配置示例见配套 Agent 的 ``docs/user/ips.rst``。

查看结果
--------

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 查询字段
     - 含义
   * - 加载代次 / Snort PID
     - 确认配置重载；正常热重载 PID 保持不变
   * - 实际检查接口
     - 实际绑定的 VPP 接口与方向
   * - 基础配置文件 / 待加载
     - 文件容器路径以及是否有尚未接受的宿主机修改
   * - 基础配置错误
     - 主配置校验或重载失败，运行中的旧配置可能仍然有效
   * - 最近错误
     - 规则或绑定运行时错误
   * - 日志目录
     - Agent 容器内的 Snort 告警路径

错误规则或基础文件不会作为成功配置接受，运行时尝试恢复上一份生效配置。
如任务补偿失败，按任务页处理；不要仅根据 Desired 资源列表判断设备已生效。
